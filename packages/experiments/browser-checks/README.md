# Browser checks

Scripts that check, in a real browser, what the unit tests cannot: how the extension, the website and the bridge between them behave. They are the checks behind the records in [docs/internals/web-app.md](../../../docs/internals/web-app.md). They are not run by CI and nothing here is a test of the repository's own code in the usual sense.

**Rules.** Every browser these scripts start is a throwaway: a fresh temporary profile, a random debugging port, headless, and all outside DNS refused (only the mapped test hosts and `localhost` resolve), so nothing is sent to a search engine or to `kiwi.moe`. Never point them at your own browser or profile, and do not change them to run headed.

**Needs** Node 24, `openssl` (a self-signed certificate for `kiwi.moe` is made on first use and ignored by git) and a Chromium binary: set `CHROMIUM` to it (the default is the macOS app, `/Applications/Chromium.app/Contents/MacOS/Chromium`). Run `node bundle-protocol.mjs` once after `pnpm install` to make `web/protocol.js`, which the test pages load.

| Script | What it checks |
|---|---|
| `chromium.mjs dnr` | `declarativeNetRequest` against addresses with a `#`, a host that cannot resolve, and web-accessible resources, with a probe extension (`ext/`); plus the bridge's cost compared with talking to the extension page directly. `optional` and `dse` check the optional `webNavigation` permission and a default search with a `#` template. |
| `firefox.mjs` | The `MessagePort` hand-over and the stream in a headless Firefox through `web-ext` (install it into `tools/`: `npm install --prefix tools web-ext`). Its DNR self-test did not run, see the record. |
| `smoke.mjs <build> <shots-dir>` | Loads a built extension, opens its search page, settings page and a search, and reports console errors and screenshots. |
| `web-smoke.mjs <build>` | The real protocol client in a page against a built extension (build it with `WXT_KIWI_WEB_DEV_ORIGIN=http://localhost:18765`). |
| `web-e2e.mjs <build> <apps/web/dist> <shots-dir>` | The built website served with its `_headers`, against the extension (same dev origin): a search, a fragment navigation, the service worker and the page opening with the server down, and the page with no extension. |
| `mode-e2e.mjs <build>` | The interface source: the redirects in both modes (the search page of `kiwi.moe`, its other pages, the old host `s.kiwi.moe`), the website's handshake, and cutting a connected page when the setting changes (dev-origin build, port 18765). |
| `bfcache-check.mjs <extension build> <apps/web/dist>` | A page opened in the same tab and then Back (the back-forward cache), then a new search: whether the link to the extension survived, and whether the page had to reload itself to recover (dev-origin build, port 18765). |
| `layering-check.mjs <apps/web/dist> [label] [screenshot-dir]` | The search suggestions open over a result with a stack of engine marks: asks the browser which element is on top at the centre of each mark (the dropdown must be), and that the best-ranked mark is still on top of the stack. No extension needed; run after building `apps/web`. |
| `preview-check.mjs <url> [shots-dir]` | The website as a host serves it (a Cloudflare preview or `kiwi.moe`), in a headless Chromium with no extension where only that host resolves: the install screen, console errors, and the service worker over https (set `WAIT_MS` longer than the default 4000 if it is not active yet). |
| `webrtc-check.mjs [idle-seconds]` | Device-sync feasibility (no extension build needed): two throwaway Chromiums, each with the probe in `ext-webrtc/` and its offscreen document (reason `WEB_RTC`), connect with no STUN, TURN or signaling server, only the compact connection codes passing between them; plus the service worker's WebRTC and WebCrypto surface, SDP munging, the certificate's lifetime and persistence, the one-way reconnection, and whether the channel outlives an idle service worker. Prints kinds of candidates, never addresses. Record: [device-sync.md](../../../docs/internals/device-sync.md). |
| `firefox-webrtc.mjs [plain\|noproxy]` | The same probe as a Manifest V2 background page in a throwaway headless Firefox, installed through WebDriver BiDi (no web-ext). `plain` turns off the mDNS names for host addresses, `noproxy` drops the dead proxy that keeps the browser's own requests off the network. |
| `peerjs-check.mjs` | PeerJS (1.5.5) in the offscreen document of two throwaway Chromiums against a **local** PeerServer (1.0.2), never the public one: its default ICE servers, what the server receives, taken and absent ids. Install first: `npm install --prefix tools peer@1.0.2 peerjs@1.5.5` (the PeerJS bundle is copied into a temporary copy of `ext-webrtc/`, not committed). |
| `relay-check.mjs [idle-seconds]` | The encrypted relay of the device-sync design: `apps/relay` (a Cloudflare Worker with one Durable Object per topic) runs locally in Cloudflare's runtime through `wrangler dev --local`, never deployed; two throwaway Chromiums meet through it with the encrypted signaling of `ext-webrtc/relay-probe.js` and open a data channel, while a third client on the same topic records what the relay sees and replays and tampers with frames, and a web page (`https://kiwi.moe` mapped to a local server, and a plain `http` page) is shown to be refused with 403. Needs only `pnpm install` at the repository root; wrangler's local state goes to a temporary directory and `.wrangler/` (ignored). |
| `firefox-relay.mjs` | The same relay from a throwaway headless Firefox: an extension background page (`moz-extension://`) connects and a frame is forwarded unchanged and not echoed, while an ordinary web page of that browser is refused. WebSockets only, no ICE. |
| `ext-webrtc/pair.html` | Not a script: a page of the probe extension for the two-device check by hand. Load `ext-webrtc/` unpacked in a spare Chromium profile on each device (never in the profile you use), open `chrome-extension://<id>/pair.html`, and carry the codes between the devices yourself; a STUN server is optional. |
| `site-shot.mjs <apps/web/dist> <shots-dir>` | The pages of `kiwi.moe` (introduction, install, getting started, privacy) under their own security policy, at desktop and phone width. |

Results are printed, and some are also written as `results-*.json` (ignored).

`release-install.mjs <apps/web/dist> <evidence-dir>` checks latest-release/history links, package hints for every browser choice, and layout at 1440/390/320px with both OS colour preferences. It serves the built homepage and Chinese/English installation guides under their actual CSP, refuses external requests and saves screenshots/results. Check public GitHub redirects and assets separately.
