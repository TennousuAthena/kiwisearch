# Extension runtime: background, worker tabs, content script

The service worker, how browser engines run in worker tabs, and the content script that reads their result pages. Overview and rules: [AGENTS.md](../../AGENTS.md). Chinese overview for people: [docs/ARCHITECTURE.md](../ARCHITECTURE.md).

## Overview

**`apps/extension`: WXT + React, Manifest V3.** `entrypoints/` holds the entry points.

## Background service worker

`background.ts` is the service worker and runs the pipeline. The new-tab page opens a `runtime.connect({ name: 'search' })` port, sends a `search` request (`query`, `mode`), and receives streamed `PortMessage`s. The same file registers the omnibox keyword, a declarativeNetRequest redirect from `https://s.kiwi.moe/s?…` to `newtab.html`, the `kiwi:*` runtime messages, and the MCP bridge with its reconnect alarm. The options page only opens on first install. It is declared `open_in_tab` (the meta tag `manifest.open_in_tab` in `entrypoints/options/index.html`; WXT's default is `false`), so "Extension options" opens a full tab instead of the small embedded view inside chrome://extensions.

## Worker tabs (`lib/tabRenderer.ts`)

Browser engines run in `lib/tabRenderer.ts`. Each `SourceId` has its own serial queue and a minimum interval between requests (`renderer.minIntervalMs`). Each engine gets one persistent, muted worker tab. All worker tabs live in one window of their own, in one grey tab group titled `Kiwi Search` (not collapsed: it is the only group in that window, and collapsing a group that holds the active tab is an edge case; `tabs.group` must be given `createProperties.windowId`, because a new group otherwise goes into the *current* window, which drags the worker tab into the user's window and closes the emptied worker window), and that window is minimized right after it is created, so search pages never appear in the window the user is working in (`windows.create({ state: 'minimized' })` alone is ignored by macOS Chromium, hence the explicit `windows.update`). The window is recreated if the user closes it. Worker state is stored in `chrome.storage.session` under `kiwiRenderer`.

## Content script (`entrypoints/engines.content.ts`)

`entrypoints/engines.content.ts` is injected into engine result pages (its `matches` come from `BROWSER_ENGINES`). A page handshakes with `kiwi:worker?` and gets the requested `count` and `mode`, so only registered worker tabs do anything. It watches DOM mutations (debounced), waits for `readySelector`, and extracts: it returns at once with `count` results, otherwise after the page has been quiet for 600ms, and at the 12s timeout with whatever is there. On a captcha or block page it sends `kiwi:blocked` with a `reason`: `login` when the engine's `isLoginUrl`/`loginSelector` match (a site the browser isn't signed in to: Zhihu, Xiaohongshu, X), otherwise `captcha` (`isBlockedUrl`/`blockedSelector`; use `':not(*)'` when no captcha markup is known). The pipeline then marks that source `blocked` (`source_blocked` carries the reason, `sourceStats[].blockedReason` keeps it) and extends its timeout to 120s. The new-tab page offers one action per reason ("去登录" / "去验证"), and only a captcha may bring the window forward by itself. Two more ways a worker page fails fast instead of waiting out the timeout: an engine's `refusedPattern` matching the page text (the site refuses outright; the content script sends `kiwi:refused`, e.g. Zhihu's risk-control JSON `code 40362`), and a page that finished loading but whose content script never said hello within 4s (`HANDSHAKE_GRACE_MS` in `tabRenderer.ts`: the browser's own error page, an HTTP 403 that keeps the requested address, a redirect to a page the engine doesn't read). Both reject the request, which `sourceStatus` records as "上次出错" with the reason. Checked in a fresh, signed-out headless Chromium: Zhihu answered the search URL with that JSON (0.8s to fail, was 13.8s) and X with Chrome's 403 page (5.0s, was 15s); a real signed-out Zhihu/X login wall was NOT seen there, so `loginSelector`/`isLoginUrl` for those are still guesses. The new-tab page shows one quiet line with a "verify" link; the worker window is brought forward only when the user clicks it (`kiwi:focus-worker`), or by itself if `renderer.focusOnCaptcha` is on. That is off by default (config migration 1→2 turned off the old saved default), and the window is minimized again once the extraction arrives.
