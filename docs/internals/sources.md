# Sources

The source registry, browser engines and API sources, Exa snippets, the two Brave sources, and what adding a source touches. Overview and rules: [AGENTS.md](../../AGENTS.md). Chinese overview for people: [docs/DEVELOPMENT.md](../DEVELOPMENT.md).

## Registry, browser engines and API sources

Sources are unified as `SearchSource` and registered in `src/sources/index.ts` (`SOURCES`). Each declares `modes`, `requiresKey` and, if needed, `requiresBaseUrl`/`requiresBrowser`:

- Browser engines (`google`, `bing`, `baidu`, `duckduckgo`, `bravesearch`, `scholar`, `baiduxueshu`, `cnki`, `wos`, `yandex`, `youtube`, `bilibili`, `zhihu`, `xiaohongshu`, `rednote`, `sogou`, `weixin`, `x`) are `BrowserEngine` objects in `src/engines/*.ts`: `buildUrl(query, count, mode)`, `matches`, `readySelector` (a selector list covering all modes), `blockedSelector`, `isBlockedUrl`, `extract(doc, pageUrl, mode)`, and an optional `resolve` for unwrapping redirect links. `makeBrowserSource` in `engines/shared.ts` wraps them as sources. Bing serves web and images through the same worker tab and queue. The YouTube engine reads the inline `ytInitialData` JSON from the page's scripts (so its `readySelector` is just `body`) instead of the custom-element DOM; the Bilibili engine reads the rendered `.bili-video-card` DOM. Zhihu and Xiaohongshu only work in a browser the user is signed in to. Xiaohongshu has two sources, `xiaohongshu` (mainland) and `rednote` (international), with separate domains and logins but the same note ids (normalized to `xhs:<id>` in `url.ts`, so both merge); `rednote` is on by default and the mainland site is opt-in. Note links keep `xsec_token`/`xsec_source`, which the site needs to open a note. Zhihu keeps its author in `meta.author`, not `meta.authors`, because `authors` marks a result as a paper for de-duplication and would merge different answers to one question. The Sogou WeChat engine (`weixin`, mode `wechat`) finds WeChat official-account articles; it returns Sogou's own redirect links (`/link?url=…`), which, opened without a Referer, land on the article at mp.weixin.qq.com (checked), so they are kept as they are and `host` is set to `mp.weixin.qq.com`. The publish time comes from the text of the `timeConvert('<unix seconds>')` script, which is never run. `sogou` (Sogou web search, off by default) also keeps redirect links and takes the site from a card's `data-url`. Neither needs a login. X (`x`, mode `x`) works only in a browser signed in to X (signed out, a search redirects to `/i/jf/onboarding/web`, which `isBlockedUrl` recognizes). It is a tab of its own and never a route of the general search; its tweets are not judged or summarized (`modeHasText('x')` is false). X polices automated use of an account, so the engine sets `BrowserEngine.minIntervalMs` (10 s), which `tabRenderer.ts` applies on top of `renderer.minIntervalMs` between request *starts*. X renders a virtualized list and renders nothing new while the worker window is minimized (page visibility `hidden`; scrolling the worker page changed nothing), so a search returns only the 4–6 tweets of the first render, and getting more would mean bringing the window forward. The engine skips promoted tweets (a bare `Ad` label), takes a quote tweet's own text instead of the quoted one's, uses the title and preview of an X Article when a post has no tweet text, and reads the counts from the `aria-label` of the action row.
- API sources (`brave`, `exa`, `deepseek`, `openalex`, `crossref`, `arxiv`, `openverse`, `pubmed`, `europepmc`, `dblp`, `searxng`) live in `src/sources/*.ts` and call HTTP through `env.fetch`. Openverse is anonymous-limited (20 results per page, 200 requests a day).

## Exa snippets

Exa returns a page as Markdown (both `text` and `highlights`; its docs call it "plain markdown-style text"), and a page often opens with a table: Wikipedia with its infobox, an annual report with pages of them. The snippet used to be `highlights[0] ?? text` squeezed to one line and cut at 300, so a result showed `| 浙江稠州商业银行股份有限公司 … | | | --- | --- | …` (seen by the user on the Wikipedia page of 浙江稠州商业银行). No Exa setting avoids it: checked with the user's key on three queries, a highlight capped at 600 characters even starts inside the table (`| --- | --- |`), and `excludeSections` changed nothing on these pages. `contents.summary` (Exa writes a description) is clean, 0 of 10 with a table, but costs 4-5 s more (5.3-6.3 s against 1.2 s) and $0.017 against $0.007 a search, which would push Exa past the 6 s soft deadline every time, so it is not used. Instead `markdownSnippet` in `text.ts` makes the snippet: it splits the Markdown into blocks and takes the first block with something to say, in page order (so a footer never comes before the content): a paragraph of prose (and the next ones until about 240 characters; a paragraph ending in a colon also takes the list after it), a list whose items are longer than menu entries, or a table of three or more columns (a ranking is what its page is about; read as `排名 地区 GDP；1 广东 …`). A two-column table is an infobox and is skipped for the prose after it; headings, code, the repeated page title and any line with a `|` (header, footer, breadcrumb) are not prose; links, images, footnote marks like `[9]`, emphasis, tags and zero-width marks are stripped; lines wrapped inside a sentence are joined without a space between two CJK characters. It reads the highlight first and `text` when the highlight has nothing; with no content block at all it falls back to a list, then a table read as `label：value` pairs, then short lines. `content` stays Markdown (the overview and the decision model read it fine). The request now uses `highlights.maxCharacters` 1500: `numSentences` is deprecated (about 1,333 characters a sentence, so "3 sentences" was up to 4,000) and `highlightsPerUrl` is ignored (every answer carried an `IGNORED_FIELD` warning). `packages/core/test/fixtures/exa.json` is 12 real results (10 for 浙江稠州商业银行, plus a five-column ranking table and an article whose text opens with a `### 来源 | … | …` byline), trimmed. Checked 2026-11-12: over 130 real results from five request shapes none kept table syntax or Markdown marks and none was empty; in the user's dev browser through the real pipeline (Exa only) 30 results on three queries were clean, at the same 1.2-2.0 s. Not checked: DeepSeek's `snippet` and SearXNG's `content` are used as given (no key for the first; the second is plain text by its API); a `[a]` or `[1]` that is real content in a snippet is dropped with the footnote marks.

## Brave: two sources over one index

Brave has two sources over one index, like the two Xiaohongshu sites: `brave` (API, needs a key; `sources/brave.ts`) and `bravesearch` (`engines/bravesearch.ts`, web mode, no key, on by default), which reads `search.brave.com/search?q=…&source=web` in a worker tab. Results are `.snippet[data-type="web"]` blocks (the page also holds an AI answer, an FAQ and a `cluster`, other `data-type`s that are skipped); the title is `.search-snippet-title` inside the link, the snippet `.generic-snippet .content` (Brave already writes the date into it, `31 March 2025 - …`, which is kept as text and not parsed into `publishedAt`), or `.inline-qa-question` for a Reddit-style card; links are direct, so there is no `resolve`. Brave's slider captcha is served at the **same address** as the results (title `Captcha - Brave Search`, `.captcha-wrapper`, `canvas.captcha-image-canvas`), so `isBlockedUrl` is not defined and `blockedSelector` does the work. Both sources share one mark (`SOURCE_MARKS`), so a result both returned is not shown as two engines agreeing; with both switched on Brave is counted twice in the RRF fusion (not deduplicated; the settings blurb says one is enough). Checked on 2026-11-12: `bravesearch.html` is the rendered DOM read from the user's own dev browser (20 results, scripts/styles/SVG removed) and `bravesearch-blocked.html` is the captcha page a cold headless Chromium got (same query, `HeadlessChrome` user agent; curl with a Chrome user agent got results, the dev browser got results and no captcha). In the real extension: the dev browser, Brave (web) as the only source through the real pipeline, 10 results in 3.2 s cold and 1.0 s warm (English and Chinese queries), status `ok`; a throwaway headless Chromium with only this source got the captcha, the content script reported it (`captcha`) and the page showed "去验证". Not known: how often an ordinary new browser is sent to the captcha, so the on-by-default choice is a guess; only web mode is read (Brave's images, news and videos are not).

## Adding a source

Adding a source touches five places: the hand-written `SourceId` union in `types.ts`, the `SOURCES` registry (typed as `Record<SourceId, …>`, so TypeScript flags a gap), its name, blurb and hover name in the message catalog (`source.label.<id>` and `source.blurb.<id>` in `catalog/options.ts`, `mark.<id>` in `catalog/newtab.ts`: typed dynamic keys, so TypeScript flags a gap) and `SOURCE_MARKS` in `lib/sourceMarks.ts` (also a `Record<SourceId, …>`; its logo goes into `assets/engine-logos`, see [newtab-page.md](newtab-page.md)), and `DEFAULT_CONFIG.sources` in `config.ts`. That last field is `Partial`, so a missing entry is not flagged; the source then silently defaults to disabled.
