# Academic mode

Smart academic search (the model reads the query, papers are verified against an index), the six extra academic sources, and the limit to English-language papers. Overview and rules: [AGENTS.md](../../AGENTS.md). Chinese overview for people: [docs/ARCHITECTURE.md](../ARCHITECTURE.md).

## Smart academic search

Smart academic search (`academic.ts`, academic mode only, not with explicit `sources`, needs `config.academic.smart` and a usable `config.llm`): while the normal sources run, the user's own model reads the query and returns JSON (`intent`, `keywords`, search text per academic API source, up to `academic.landmarks` paper titles); `parsePlan` clamps it (the reply is data, never instructions). Each named title is looked up in OpenAlex (Crossref when OpenAlex is off) by `verifyPapers`; a title the index doesn't have is thrown away, so the model's memory alone never puts a paper on the page, and with neither index on nothing is shown. The verified papers go first into the fusion (so their rank counts even if a source also returned them), then come second-round lists: the model's search text on each API source whose text differs from the typed query, and a most-cited pass (`cited_by_count:desc`) on OpenAlex. Browser sources are not queried a second time (a tab to queue, a captcha to risk). The whole plan is bounded by `academic.timeoutMs` (12s) and the pipeline waits for it even past the soft deadline, so its papers are in the first full list; a model error or timeout just leaves the plain search. Events: `academic_plan` (`plan`, `landmarks`, or `error`); `PipelineResult` carries `plan` and `landmarks`, and MCP `search` reports both. The page shows the intent line, the search text folded, and a "核心文献" block (`entrypoints/newtab/AcademicPlan.tsx`, `pickLandmarks` in `lib/results.ts` matches them in the fused list by DOI or whole title) above the list, which no longer repeats them.

## Academic-mode sources

Six more `academic`-mode sources, all keyless and all opt-in except PubMed (`DEFAULT_CONFIG`): `pubmed` (on by default), `europepmc`, `dblp`, `baiduxueshu`, `cnki`, `wos` (off). The three browser ones return only what the user's own browser session can see; none ships a key or account.

- `pubmed`: `esearch` (JSON, relevance order) then one `efetch` (XML, the only format with abstracts), so two requests a search against NCBI's 3 a second without a key; a user-supplied `apiKey` is sent as `api_key` on both. Over the limit NCBI answers 200 with an `error` field, which is thrown. Links `pubmed.ncbi.nlm.nih.gov/<pmid>/`; skips queries with no Latin letter. The XML parser needs lower-case tag selectors (`pubmedarticle`) and reads the article's own DOI from `ELocationID` / the direct `ArticleIdList` because the reference list holds hundreds of other IDs.
- `europepmc`: REST `search`, `resultType=core`. A `MED` record links PubMed (same URL as the PubMed source, so the two fuse by key); others link `europepmc.org/article/<source>/<id>`. Preprints have no `journalInfo` (the publisher stands as venue) and abstracts carry markup, which is stripped.
- `dblp`: no abstracts; the snippet is the byline. dblp.org sits behind an Anubis proof-of-work bot check that answers HTTP 202 HTML instead of JSON to some clients (it did, from every host and user agent tried on the capturing machine); the source throws "bot check" rather than returning nothing. Links the record's `ee` (DOI / arXiv / publisher link, so it fuses) or DBLP's own page.
- `baiduxueshu`: `xueshu.baidu.com/s?wd=` settles on the single-page app at `/ndscholar/browse/search` (both are in `matches`); cards are `div.paper-wrap.result`, links are Baidu Scholar's own detail pages. A cold headless profile got "百度安全验证" at the *same* address, so `blockedSelector` keys on the captcha library's own script/link files; opening the site's home page first got real results.
- `cnki`: kns8s search. A cold headless profile was redirected to `/verify/home?captchaType=blockPuzzle` (slider captcha), which `isBlockedUrl` recognizes. The result-table parser is from memory, unverified against a real page.
- `wos`: with no institutional IP or login, the app sends the browser to `access.clarivate.com/login` (another host, so it is in `matches`; `isBlockedUrl` recognizes the host and the source reports `blocked` instead of timing out). The search address and the `app-record` / `data-ta` parser are from memory, unverified (they need an account).

## Language limit

Academic mode can be limited to English-language papers (`RunOptions.language`, `AcademicLanguage` = `any` | `en` in `types.ts`; `any` is the default and limits nothing; core is written by language code, so another language is a table entry in `academicLanguage.ts` and in each source below, not a new structure). It applies to academic mode only: a source a general search routes in runs without it, and `runSearch` ignores the option in any other mode. The cache key of an academic source carries the language (`academic:en|…`), so a result fetched under one setting is not reused under the other.

Two layers, because the first is not enough:
- **The source is asked.** `ctx.language` reaches `SearchSource.search`, and a browser engine gets it as the fourth argument of `buildUrl(query, count, mode, language)` (`BrowserRunOptions.language`, through `makeBrowserSource` and `tabRenderer.ts`). OpenAlex adds `filter=language:en`, PubMed `(query) AND english[la]`, Europe PMC `(query) AND LANG:eng` (the query goes in parentheses, so an `OR` is not captured by the `AND`), Google Scholar `lr=lang_en`. Crossref has no language filter (its API answers `filter-not-available`), arXiv and DBLP are English anyway, and nothing is known about the parameters of Baidu Scholar, CNKI and Web of Science, so those return what they have.
- **Every result is checked by its title** (`applyAcademicLanguage` in `academicLanguage.ts`, the first step of `tidy` in `pipeline.ts`, so partial lists and late merges get it too). A title reads as English when it has no Chinese, Japanese or Korean characters and at least one Latin letter (`isEnglishTitle`). A result that fails is hidden as `{ reason: 'language' }` and moved behind the others; the page lists it in the hidden section ("语言不符：当前只看英文文献") and MCP lists it under `structuredContent.hidden`. A result already hidden for another reason keeps that reason. The check cannot tell English from another language in Latin letters (a German title passes), and a title that quotes a Chinese term does not pass.

The smart search takes the limit too (`planAcademicQuery`, `verifyPapers`, `searchWithPlan`): the plan prompt gets a "Language limit" block that overrides the keyword rule (every search text and keyword in English, no Chinese terms, only papers published in English, English titles; `intent` stays in the query's language), the title checks and the most-cited pass ask OpenAlex with the filter, and a named paper whose title does not read as English is dropped. Without an AI model a Chinese query is searched as typed; the page then says so in one line (`newtab.academic.languageNoPlan`, shown when the query has CJK characters, the limit is on and no plan came back).

The page's choice (the "不限语言" / "仅英文" chips in their own row under the academic toolbar, `entrypoints/newtab/App.tsx`) is kept in `chrome.storage.local` under `academicLanguage` (`lib/academicLanguage.ts`), not in `config`: the settings page saves the whole config and could overwrite it. It is read before the first search of a page, sent with every academic search (`SearchRequest.language`), and changing it runs the same search again in the same history entry. It is not in the address. MCP `search` and `answer` take an optional `language`; without it they search unlimited, whatever the page last chose.

Checked on 2026-11-13, through the real source code with real requests (a temporary test, not kept): OpenAlex, Europe PMC and PubMed with `deep learning` all return English titles with and without the limit, and an `OR` query with quotes works with the parentheses on all three. For the query `深度学习` OpenAlex with `language:en` still returned 10 works with Chinese titles (OpenAlex tags them `en`), so the filter alone is not enough and the title check is what keeps them off the page; Europe PMC returns English titles for that query with or without `LANG:eng`; PubMed skips a query with no Latin letter. In a throwaway headless Chromium with the built extension (`~/.kiwi-search/e2e/lang-e2e.sh`, OpenAlex, Crossref, arXiv and PubMed): the chips are on the academic tab and default to no limit; clicking English stores it, runs the search again and shows only English titles (38 results); a new page opens with it already on; `深度学习` with the limit and no plan shows 0 results and 20 hidden with the reason and the one-line note, and going back to no limit shows 19 Chinese-titled works; with the dev model and the smart search on, the same Chinese query got English search text for OpenAlex, arXiv and PubMed and English keywords, 44 English papers shown and 20 hidden. Unit tests: `academic-language.test.ts`, `server.test.ts`, `results.test.ts`.

The layout of the chips was checked by screenshot and by measuring the boxes (`~/.kiwi-search/e2e/lang-shot.sh`, 2026-11-13): dark and light at 1280 px wide, dark at 390 px, English only on, and the state with nothing left to show (language row alone, the one-line note, the hidden results below); the language row is left-aligned with the first time chip, below the toolbar, inside the column, and the page does not scroll sideways. The first version of this change was only checked through the DOM and had the language chips right-aligned on a second line.

Not checked: Google Scholar's `lr=lang_en` (a plain request from Node gets HTTP 403 "Sorry" with or without it, and it was not run in a browser); Baidu Scholar, CNKI, Web of Science and Crossref only through the title check; Firefox; the dev browser; any language but English.
