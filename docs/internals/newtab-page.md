# New-tab page

The search page: session and reducer, what the page shows, source marks and logos, site icons. Overview and rules: [AGENTS.md](../../AGENTS.md). Chinese overview for people: [docs/ARCHITECTURE.md](../ARCHITECTURE.md).

## The new-tab page

The new-tab page: `lib/useSearchSession.ts` owns the port, keepalive and the built-in-model summary; `lib/searchState.ts` is the pure reducer over `PipelineEvent`s; `lib/results.ts` and `lib/justify.ts` are pure helpers (`modeHasOverview` there mirrors core's `modeHasText`; importing core into the page bundle would pull in the parsers). Components are in `entrypoints/newtab/`. In a general search the community posts that the intent routes pulled in leave the list and gather in a "各平台怎么说" block after the first three results (`splitPlatforms`, at least two posts, at most six and three per platform; `PlatformStrip.tsx`) with a link into each platform's own tab; the platform tabs (知乎, 小红书, 公众号, X) are folded under one "社区" tab (`ModeTabs.tsx`, `COMMUNITY_MODES`). The page shows which engines returned a result as small marks after the site name (`lib/sourceMarks.ts` orders and dedupes them by rank, `entrypoints/newtab/SourceMarks.tsx` renders them: each logo on a small round chip, the chips stacked tight with the best-ranked on top and fanning out with a gap on hover or focus; none in the folded hidden section). Two or more distinct engines give the clear stack; a result only one engine returned gets that one mark too, class `solo`, drawn at opacity 0.5 (0.85 on hover/focus) so it does not compete with the title (the user asked for this on 2026-11-12; before, one engine showed nothing). 0.5 was chosen from 2x screenshots in light and dark: at 0.4 a dark logo such as Exa's is almost gone on the dark page. Aliases share a mark (`brave`/`bravesearch`, `xiaohongshu`/`rednote`), so they never count as two engines agreeing. The logos are real brand logos, never drawn here: files in `apps/extension/assets/engine-logos/` (from SVG Logos and Simple Icons, both CC0, from Font Awesome Free Brands (CC BY 4.0, the Yandex Y) or the brand's own site icon), with their origin and licence in `logos.json` and `NOTICE.md` (a test insists on both). `scripts/gen-source-icons.mjs` turns them into data URIs in `lib/sourceIcons.ts` (`dark` is a variant for the dark page, `invertInDark` a black raster that is inverted there), so nothing is fetched; each mark is a `<picture>`/`<img>`. A new engine needs its logo file and a `logos.json` entry; if no collection carries it, take the brand's own site icon, and never invent a letter badge. Beyond that, a captcha prompt is the only place a source is named. Site icons in the result headers come from the background (`lib/faviconService.ts`, message `kiwi:favicon`; `lib/favicon.ts` is the pure part): Chrome's `_favicon` API is *not* enough on its own, because it only serves icons the browser already holds from visits and bookmarks and answers every other site with the same placeholder globe (checked: GitHub, Stack Overflow, Wikipedia and a made-up host returned byte-identical 646-byte images). So the order is the browser's own icon (the placeholder is recognized by comparing with the answer for a made-up host), then the site's `/favicon.ico` and the `<link rel="icon">` of its home page (no cookies, no referrer, public host names only, image type decided from the bytes because many sites answer a missing icon with a 200 HTML page), then a letter badge. Results are cached per host in `storage.local` (`favicon:<host>`, 7 days for hits, 6 hours for misses, pruned to 400 entries), and at most 4 site requests run at once. The cost of this is that a site you have never visited receives one icon request (and one home-page request when it has no `/favicon.ico`) when it shows up in results; no third-party icon service sees your results. The URL is `newtab.html?q=…&m=images|video|academic|zhihu|xiaohongshu|wechat|x`, and new searches use `pushState`.
