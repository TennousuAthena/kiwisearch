# New-tab page

The search page: session and reducer, what the page shows, source marks and logos, site icons. Overview and rules: [AGENTS.md](../../AGENTS.md). Chinese overview for people: [docs/ARCHITECTURE.md](../ARCHITECTURE.md).

## Where the code is (2026-11-14)

The page's code no longer lives in `apps/extension`. The components are in `packages/app/src/app/`, its helpers in `packages/app/src/lib/` and the message catalogs in `packages/app/src/i18n/`; `apps/extension/entrypoints/newtab/main.tsx` only calls `mountSearchApp()` with the extension's `KiwiHost` (`apps/extension/lib/extensionHost.ts`). Everything the page used to ask the browser for goes through that interface: the search and summary ports, site icons, focusing a worker tab, blocking or boosting a site, the stored interface preferences (`PreferenceBackend`), the academic language and the two page addresses. The page itself makes no `browser.*` call, so the same code can run on a website. The rest of this file describes the page as before; paths in it point at the new places. Design and status of the move: [web-app.md](web-app.md).

## The new-tab page

The new-tab page: `packages/app/src/lib/useSearchSession.ts` owns the port, keepalive and the built-in-model summary; `packages/app/src/lib/searchState.ts` is the pure reducer over `PipelineEvent`s; `packages/app/src/lib/results.ts` and `packages/app/src/lib/justify.ts` are pure helpers (`modeHasOverview` there mirrors core's `modeHasText`; importing core into the page bundle would pull in the parsers). Components are in `packages/app/src/app/`. In a general search the community posts that the intent routes pulled in leave the list and gather in a "各平台怎么说" block after the first three results (`splitPlatforms`, at least two posts, at most six and three per platform; `PlatformStrip.tsx`) with a link into each platform's own tab; the platform tabs (知乎, 小红书, 公众号, X) are folded under one "社区" tab (`ModeTabs.tsx`, `COMMUNITY_MODES`). The page shows which engines returned a result as small marks after the site name (`packages/app/src/lib/sourceMarks.ts` orders and dedupes them by rank, `packages/app/src/app/SourceMarks.tsx` renders them: each logo on a small round chip, the chips stacked tight with the best-ranked on top and fanning out with a gap on hover or focus; none in the folded hidden section). Two or more distinct engines give the clear stack; a result only one engine returned gets that one mark too, class `solo`, drawn at opacity 0.5 (0.85 on hover/focus) so it does not compete with the title (the user asked for this on 2026-11-12; before, one engine showed nothing). 0.5 was chosen from 2x screenshots in light and dark: at 0.4 a dark logo such as Exa's is almost gone on the dark page. Aliases share a mark (`brave`/`bravesearch`, `xiaohongshu`/`rednote`), so they never count as two engines agreeing. The logos are real brand logos, never drawn here: files in `packages/app/assets/engine-logos/` (from SVG Logos and Simple Icons, both CC0, from Font Awesome Free Brands (CC BY 4.0, the Yandex Y) or the brand's own site icon), with their origin and licence in `logos.json` and `NOTICE.md` (a test insists on both). `packages/app/scripts/gen-source-icons.mjs` turns them into data URIs in `packages/app/src/lib/sourceIcons.ts` (`dark` is a variant for the dark page, `invertInDark` a black raster that is inverted there), so nothing is fetched; each mark is a `<picture>`/`<img>`. A new engine needs its logo file and a `logos.json` entry; if no collection carries it, take the brand's own site icon, and never invent a letter badge. Beyond that, a captcha prompt is the only place a source is named. Site icons in the result headers come from the background (`lib/faviconService.ts`, message `kiwi:favicon`; `lib/favicon.ts` is the pure part): Chrome's `_favicon` API is *not* enough on its own, because it only serves icons the browser already holds from visits and bookmarks and answers every other site with the same placeholder globe (checked: GitHub, Stack Overflow, Wikipedia and a made-up host returned byte-identical 646-byte images). So the order is the browser's own icon (the placeholder is recognized by comparing with the answer for a made-up host), then the site's `/favicon.ico` and the `<link rel="icon">` of its home page (no cookies, no referrer, public host names only, image type decided from the bytes because many sites answer a missing icon with a 200 HTML page), then a letter badge. Results are cached per host in `storage.local` (`favicon:<host>`, 7 days for hits, 6 hours for misses, pruned to 400 entries), and at most 4 site requests run at once. The cost of this is that a site you have never visited receives one icon request (and one home-page request when it has no `/favicon.ico`) when it shows up in results; no third-party icon service sees your results. The URL is `newtab.html?q=…&m=images|video|academic|zhihu|xiaohongshu|wechat|x`, and new searches use `pushState`.

The academic tab has the time chips and the citation sort in one row (`.toolbar`, only when there are results to filter) and the language chips ("不限语言" / "仅英文") in a row of their own below it (`.lang-chips`, shown for every academic search, also when nothing is left to sort). They are not one row because the result column is 42rem and the time and sort chips alone nearly fill it: with a third group in the same flex row, the language chips wrapped to a second line and, pushed right by `margin-left: auto`, sat flush right under a flush-left first row. The choice is stored under `academicLanguage` and is not in the address; how it reaches the pipeline and what it does is in [academic.md](academic.md).

## Quick answers

General web searches reuse the existing overview request and citation snapshot for a factual quick answer. The prompt reserves a leading Markdown H1 for the short answer, followed by one cited explanatory paragraph. `packages/app/src/lib/quickAnswer.ts` extracts that shape only in web mode once the paragraph is complete (a paragraph boundary, or successful summary completion). The headline must be plain text of at most 100 Unicode characters and the explanation at most 700, with existing HTTP(S) source citations. Unknown, malformed, escaped, code-wrapped or linked citation markers, structured blocks and failed model output remain an ordinary overview. These checks validate format and references; they do not establish that the model's claim is true.

`QuickAnswer.tsx` renders the headline as React text and the explanation through the overview's sanitized Markdown renderer. The block stays immediately above the first result in the results column at every viewport width. Its small AI label, 26–32px headline, 15px explanation and bottom separator use existing theme tokens. Citation links open their original source and highlight the matching result on hover or keyboard focus. The extracted text is removed from the ordinary overview; when no text remains, the overview and its right rail are omitted. Unexpected following content can still render as an overview with the same citation numbers. API and Chrome built-in output share this page-side handling, without importing core at runtime or changing the event protocol or stored settings.

Checked on 2026-11-13: seven parser tests cover completed and partial streams, adjacent citations, optional remaining overview, mode isolation, failed generation, invalid/unsafe citations, compact plain headlines and prose-only details. Catalog copy, hardcoded-text and i18n guards passed. Live Chromium activation, visual rendering and model compliance are integration checks recorded separately; parser tests alone do not verify those behaviors.

## News searches

The news tab follows video and is query-driven; selecting it without a query does not start a search or show a feed. `NewsToolbar.tsx` exposes publication windows (`any`, `day`, `week`, `month`) and ordering (`relevance`, `date`). News URLs retain `m=news` even before a query is entered, with nondefault conditions in `range` and `sort`; Back and reload restore all three. Leaving news removes its conditions from the address. Refresh repeats the same query and conditions with `refresh: true`; it bypasses source-result caches through the normal pipeline. News options are per-search URL state, not stored configuration.

`NewsResult` in `Results.tsx` shows publisher, optional byline, publication or update evidence, source marks and an optional thumbnail. A failed thumbnail disappears without hiding the article. `packages/app/src/lib/news.ts` is a page-side, type-only-core helper: date-only evidence stays a date in every timezone, precise timestamps use the reader's timezone, and unparsed source time text remains visible. Update and retrieval times never become publication dates. Limited publication ranges can leave time-hidden results, whose counts and reasons use the existing folded hidden section.

The overview uses the existing numbered citations. At `summary_start` the reducer records visible article evidence; changed evidence in `late_results` marks the overview stale and offers an explicit refresh. It preserves the current overview and citations while late sources settle, and does not generate another overview automatically. Engine agreement, ordering changes and newly hidden results alone do not mark it stale. The completed pipeline supplies the overview snapshot time in `news.summaryAt`. Main mode buttons wrap on small screens; the community popup stays outside scrolling/clipping containers and is clamped to the viewport, with Escape returning focus to its trigger.

Checked on 2026-11-13: frontend tests cover URL round trips (including empty news and invalid conditions), date precision/timezone handling, raw and unknown time evidence, hidden-time labels, and late-result overview state. Typecheck passed. Browser layout and live search checks belong to the integration verification in [news.md](news.md); these unit tests do not prove browser rendering or upstream coverage.

## Search interaction and reading state (2026-11-13)

`App.tsx` owns a bounded, 12-entry in-memory history cache keyed by `history.state.kiwiEntry`. Each snapshot retains the reducer state, draft, mode and conditions, expanded overview/snippets/hidden section, selected image, temporary site filter and reading anchor. Back/Forward restores it through `useSearchSession.restore`, which stops any unfinished work and never reconnects to a model. Entries that were evicted, or a browser Back that creates a new document instead of restoring its memory, offer an explicit repeat-search action. Refresh and a newly opened query URL still run that query. No queries, results or AI text are written to persistent history. Result-key/viewport offsets keep reading position across late result and filter changes, falling back to absolute scroll position if the anchor disappears.

`SearchBox.tsx` offers at most six matches from the last twelve submitted queries in the current tab. Arrow keys preview a suggestion; Escape restores the draft; Enter submits once; composition events suppress IME Enter. A navigation reset token closes suggestions and discards stale preview state. `/` focuses and selects the query except in editable controls. The preference can disable and clear this tab's recent-query memory. There is no remote suggestion endpoint.

Result snippets fold after three lines with explicit expansion. Source marks open a keyboard-accessible, viewport-clamped nonmodal popover; pointer, Escape and focus-leave close it. Site actions distinguish temporary filtering of already fetched results from persisted block/boost preferences. The latter use the serialized settings patch protocol and a domain-specific undo receipt, rather than replacing a full configuration. Undo declines to overwrite a subsequent change to the same domain. Immediate result feedback uses a local overlay while the persisted rule applies to later searches. `data-result-key` identifies text, image, note and platform rows for reading anchors.

AI controls share one summary preference: automatic, on demand, or off. Summary-only generate/retry/stop uses an independent port and retains search results; retry reuses the checked evidence, whereas explicit fresh generation uses current results. The overview has a bounded scrollable viewport during streaming and an explicit expansion control. Copy includes the full answer (including a separately rendered quick answer) and the cited source URLs. Citations respond to keyboard focus as well as hover, and the source list exposes ordinary links. News keeps its original evidence time/staleness behavior; updating a stale overview does not repeat the source search.

Quick settings and the full settings page share per-field `ui:*` preferences for theme, summary, result opening and recent suggestions. The theme sets a root data attribute, including system changes, and source logos use the same resolved theme. The default opening behavior remains a new tab; ordinary unmodified links can instead open in the current tab. Modified clicks retain browser behavior. Browser/connection interruption, user stop, unavailable sources, failed sources, filtered-empty and genuinely empty searches have distinct copy and relevant recovery actions; source diagnostics are collapsed by default.

Verification and limits for this implementation are recorded after the integrated browser check below. Unit tests use mocked ports/storage and do not establish live upstream behavior, Chinese IME behavior or assistive-technology conformance.
