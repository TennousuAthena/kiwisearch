# Shopping search

Shopping is a standalone mode after News, before Academic. It queries Taobao, JD, Xianyu and Amazon in the user's own browser using the existing worker tabs, cookies, queues and login/captcha flow. Taobao, JD and Amazon default to enabled and Xianyu to disabled; only a shopping search uses them. Amazon is `amazon.com`, which chooses the store from the visitor's IP, so the settings page calls it "国际站". No account, API key, proxy, new configuration field or migration is introduced.

## Results and limits

The optional `product` object carries `thumbnail`, `price`, `shop`, `sales` and `rating`. Each field is source text or a validated image URL. Missing values remain absent. Currency, coupons, variants, regional delivery and account prices are not normalized; Kiwi does not infer the lowest price or stock availability. The card links to the actual product, preserving a known SKU or seller/offer identity. Source markup, URL rules and fixture provenance are documented in [sources.md](sources.md).

Shopping uses URL-only fusion, including partial and late results, so similar product titles from different shops stay separate. It never calls the intent, judgment, reranking or overview models, including when results arrive after login or the soft deadline. Domain preferences and block lists still apply, and hidden products remain expandable. `perSourceCount` and the normal five-minute cache apply.

The page keeps the query while changing modes, supports `m=shopping` URLs, and shows a responsive product grid, original displayed prices and source marks. Empty results and login blocks use the existing status actions. There is no price sorting or generated comparison. Settings group all three sources under Shopping. MCP `search` accepts `shopping` and keeps product metadata; `answer` rejects it because there is no text overview.

## Xianyu (2026-11-16)

`xianyu` (`engines/shopping.ts`) reads `www.goofish.com/search?q=…`, Alibaba's second-hand marketplace. It is the least verified source here, and the reasons are what shaped it.

**What the page is.** A client-rendered React app: the served HTML is an empty shell, and the cards come from a signed API call the page makes itself (`mtop.taobao.idlemtopsearch.pc.search`), so there is nothing to fetch and parse outside a browser. The parser therefore reads the DOM, like the other shopping engines. Its structure was taken from the site's own public code (`g.alicdn.com/idle-pc/xy-site/0.0.184/js/p_search-index.js` and `css/p_search-index.css`, read on 2026-11-16): one `a[class*="feeds-item-wrap--"]` per card whose `href` is `…/item?id=<id>&categoryId=<category>`, a title row whose `title` attribute is the plain title, tag spans (`cpv--`), a price made of `sign`, `number` (or `chinese` for a price in words), `decimal` and `magnitude` parts, `price-desc` text ("N人想要"), and the seller's name. Class names carry a build hash after `--`, so the selectors match prefixes. Four things came from reading that component rather than guessing: a card keeps only the item id (the category is dropped), a card never drawn on screen keeps only the site's two placeholder pictures (so no thumbnail, not a wrong one), the cents may or may not carry the point, and "万" and a unit sit outside the amount's element.

**What it maps to.** `product.price` is the amount as written (`¥1810`, `¥99.50`, `¥1.2万`, or the words when there is no amount), `product.shop` the seller's name, `product.sales` the `price-desc` text. That text is how many people *want* the item, which is the nearest thing a listing has to sales and is not a count of sales. The item's tags and service labels go to `snippet`.

**Why it is off by default and slow.** It only answers a browser signed in to the user's Alibaba account, and it is strict about automated visits: its own risk control answers with a slider, and third-party tools report that frequent calls end in a risk-control error and that a headless browser is not accepted. The gap between two visits is 10 seconds (`minIntervalMs`, as for X) and the working allowance 30 seconds (`minTimeoutMs`, the page signs its own request first). A source that spends an account's standing with a site should not switch itself on, and a new default-on source would switch on for every user whose saved settings predate it.

**What was checked on 2026-11-16.** One visit to the search page in a fresh headless Chromium with no profile and no account (no extension, no credentials, one page load). The page answered with a notice, not results: "非法访问 为了保障您的体验，请使用正常浏览器访问闲鱼~". That page is the real fixture `xianyu-refused.html` (body only, scripts removed). A refusal is neither a login wall nor a captcha, so the engine has `refusedPattern`, which fails the source at once with that text instead of waiting for results that will not come; the pattern needs both sentences, so a listing whose title says "非法访问" is not mistaken for it. The success page is the **hand-written** fixture `xianyu.html` (its first line says so), made from the component's source; its item ids have 19 digits, above any id the site has issued. `shopping.test.ts` covers the URL, the cards, the price forms, the photo rule, what is left out, the refusal and the login and punish addresses; `shopping-timeout.test.ts` the 30-second baseline. The logo is the icon the site declares in its page head.

**Not checked.** Any page of results, signed in or not: so the price, want count, seller and photo selectors, and whether the card's `a` is the element that carries the class, are as the bundle says and not as a live page shows. The login and captcha selectors (the `mini_login.htm` frame the bundle builds, and Alibaba's baxia widget as on Taobao) were never seen on a Xianyu page; the punish path is assumed to be Taobao's. Whether the minimized, non-headless worker window in the user's own browser is accepted or refused like the headless one. How the pre-render placeholder images behave in a minimized window (the cards may keep only placeholders until the window is shown). Firefox. The account risk is real and not measured. To check: sign in to goofish.com in the browser Kiwi runs in, enable 闲鱼 in the settings, search once from the shopping tab, and compare the result with this section.
