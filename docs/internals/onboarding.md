# Onboarding

The page a new install opens: what it shows, the network check, the three questions before Baidu, and what was verified. Overview and rules: [AGENTS.md](../../AGENTS.md). Chinese overview for people: [docs/USAGE.md](../USAGE.md).

## The page (2026-11-16)

`entrypoints/onboarding/` builds `onboarding.html`, one extension page with five steps switched in place (no navigation between pages). `background.ts` opens it from `runtime.onInstalled` only when `reason === 'install'`; an update or a reload never does, so existing users do not see it. The settings page no longer carries a first-run section: "高级 → 使用引导" has a "重新运行引导" button that opens the page again, and the old copy of the default-search and sign-in instructions stays there.

1. **Welcome.** Three points (many sources from the user's own browser, merged with content farms folded, a cited AI overview with the user's own model), one line on having no accounts or servers, and "开始" with a line saying what the check is about to do. Nothing happens before that click.
2. **Sources.** The click starts the network check (below) and shows the sources group by group. The web group is open; the others show their enabled sources as chips until opened. Each row has the real switch, the brand logo (`SourceLogo` in `packages/app`), and what the check found. A summary says which sources were switched off; when fewer than two keyless web engines are left it offers Sogou, Yuanbao and Yandex as one-click buttons. "重新检测" runs it again.
3. **Sign-ins.** The enabled sources that need a session (`SOURCE_INFO[id].login`) and were not found unreachable, each with "去登录" (opens the site in a normal tab). A status is shown only once a search has recorded one (`sourceStatus`); right after installing there is none.
4. **AI models.** The overview model (`LlmFields`, the same presets and test button as the settings page) and the decision model (`DecisionFields`, TypeSafe Jev preset). Editing the decision model keeps `judge.provider` at `systemone`. "跳过这一步" moves on; nothing here is required.
5. **First search.** The interface choice (`InterfaceSource`), a search box and three example queries, and the default-search instructions folded (`DefaultSearchSteps`, shared with the settings page). A search, an example or "完成" marks the guide done and moves the tab to the chosen interface (the site, or `app.html`).

Every change is saved as it is made, through the same `saveSettings` diff as the settings page; the page had to be added to `isExtensionPageSender` (`lib/summaryRequest.ts`) for the background to accept its updates. `storage.local.onboarding` is `{ done, step? }`: the step is saved on every move so a closed tab resumes there; `done` is set by finishing or by "跳过引导" (which opens the settings page). Opening the page again when `done` is set starts from the welcome. No config field was added and there is no migration.

## The network check

`lib/reachability.ts`. `PROBE_URLS` is typed over `SourceId`, so a new source must name an address (`null` only for SearXNG, the user's own server): a small page on the host the source actually searches (an icon, `generate_204` for Google, the root of an API). `probeSources` sends one `GET` per source, all at once, from the onboarding page (it has the extension's host permissions), with `credentials: 'omit'`, `cache: 'no-store'`, `redirect: 'manual'` and no referrer, and gives each up after 5 s. A redirect is not followed: it counts as an answer, because the target is often a CDN host whose reachability says nothing about the search page (followed, the first throwaway run marked Taobao, Zhihu and PubMed unreachable for that reason). Any status counts as reachable, 403/429/451 as limited, a network error or the timeout as unreachable. The body is never read.

`planFromProbe` only switches sources off: a source that is on and unreachable is turned off; a source that is off by default stays off whatever the check found; a source the user switched by hand during the check is left alone. It never offers Baidu.

What the check cannot say: a site that answers may still put a search behind a captcha or a login; the answer depends on the proxy in use at that moment; a reachable API still needs its key (the row says so for DeepSeek, Exa and Brave API when they are on without one).

## Baidu: three questions

`lib/sourceConfirm.ts` gives the questions asked before a source is switched on: one for Kagi (its existing text), three for Baidu, none for the rest. `EnableSourceDialog` (settings page and onboarding page) walks them in one `ConfirmDialog`: "是否开启百度？", "真的要开启百度吗？", "仍要开启百度吗？". Nothing in the dialogs says how many questions there are or which one this is (a "第 n 次确认，共 3 次" line and "最后确认" in the title were removed on 2026-11-16 at the owner's request, and a test checks the wording for counts). The confirm button is in a different place at each question, set by `ConfirmStep.layout`: at the right (`end`), then at the left with cancel beside it (`start`), then in a centred column with cancel above it (`stack`), so the same click repeated lands on empty space or on cancel, never on confirm. The buttons are in the page in the order they are drawn, so the keyboard follows the eye. Focus returns to the cancel button at every step; the confirm button of steps 2 and 3 stays disabled for 0.8 s and 1.2 s; on the last step "保持关闭" is the highlighted button and "开启百度" the plain one. Any cancel leaves Baidu off. The second question's text says only what is known from the project's own checks (an extra source to wait for, its cards in the results); an earlier draft also named promoted results and Baijiahao articles, which no capture here supports, so it was dropped. Baidu stays off by default (`DEFAULT_CONFIG`), and nothing in onboarding switches it on.
