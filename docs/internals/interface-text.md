# Interface text (i18n)

Message catalogs, how text is read, what the guard tests enforce. Overview and rules: [AGENTS.md](../../AGENTS.md). Chinese overview for people: [docs/I18N.md](../I18N.md).

## Interface text

**Interface text** is never written in a component or helper. All of it is in typed message catalogs, `apps/extension/lib/i18n/catalog/{newtab,options,worker}.ts` (merged in `zh-CN.ts`, which is the source language), read with `t(key, params)`, `tr` for a sentence with elements in it (`<link>…</link>` tags, `rich.tsx`, React pages only) and `raw` for text with braces of its own (keys ending `.raw`). Keys and `{placeholders}` are type-checked; a table is read with a dynamic key such as ``t(`mode.${mode}`)``, which compiles only if every member has a message. Never call `t()` at module top level (the language is chosen in `initLocale()` when a page or the worker starts, from `navigator.languages`; only `zh-CN` exists today). The few sentences core writes for the user (why a feature was skipped, the name of the user's own block rules) go through `Env.messages` (`CoreMessages` and its Chinese defaults in `core/src/messages.ts`; the extension fills it from the catalog in `makeEnv`, `lib/i18n/coreMessages.ts`); the rest of core's Chinese is data or prompts. Guards: `test/noHardcodedText.test.ts` fails on any string, template or JSX text with CJK in `entrypoints/` and `lib/` (put `i18n-ignore` on a line of data that only looks like text), `test/copyStyle.test.ts` runs the machine-checkable rules of `DESIGN.md` "Copy" over the catalog, `test/i18n.test.ts` checks the format and that a translation keeps the source's placeholders, `test/i18n.types.tsx` (run by `tsc`) the key and placeholder types, `test/coreMessages.test.ts` that the catalog and core's defaults say the same. Not covered: the MCP package's output, the manifest's name and description, plural forms. How to add a language and the full list: `docs/I18N.md`.
