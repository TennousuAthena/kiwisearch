# 界面文字与多语言

界面里的每一句话都不写在组件里，而写在语言包里，组件只按键去取。现在只有简体中文一种语言；这样做是为了以后加语言时不用再翻 40 个文件。文案本身怎么写，见 [DESIGN.md](../DESIGN.md) 的 “Copy” 一节。

## 结构

语言包在 `packages/app/src/i18n/`：

| 文件 | 内容 |
|---|---|
| `catalog/newtab.ts`、`catalog/options.ts`、`catalog/worker.ts` | 全部文案，按使用的地方分：新标签页、设置页、后台（标签渲染器、MCP 桥、地址栏、core 要的几句话）。每个文件是一个 `as const` 对象，键是点分的名字，值是文案 |
| `zh-CN.ts` | 把三个文件合成一份；同一个键写在两个文件里会在加载时报错 |
| `runtime.ts` | 消息格式和取词，不依赖浏览器和 React，后台、页面、测试共用 |
| `index.ts` | `t`、`raw`、`initLocale`、`MessageKey`；以及已有语言的清单 |
| `rich.tsx` | `tr`：文案里带链接、`<code>` 等元素时用 |
| `coreMessages.ts` | 把 core 要写给用户的几句话按当前语言交给 core |

三个目录的划分按“谁在用”，不按语言；加一种语言不需要动它们的划分。

## 怎么用

```ts
t('newtab.status.resultCount', { count: 3, duration: '1.2 秒' }); // "3 条结果（1.2 秒）"
t(`mode.${mode}`);                                                  // 动态键：表里少一项就是类型错误
raw('options.decision.protocol.raw');                               // 自带花括号的文字（代码样例）
tr('options.start.keys', { tags: { aiLink: (text) => <a href="#ai">{text}</a>, sourcesLink: (text) => <a href="#sources">{text}</a> } }); // 文案里的元素
```

- **占位符**写成 `{名字}`，按含义取名（`count`、`duration`），不写 `{0}`。键和占位符都有类型：键不存在、少传或多传参数都是 `tsc` 报错。
- **元素**写成 `<名字>…</名字>`，用 `tr` 渲染，每个名字对应一个函数。这样译文可以把链接放在语法需要的位置。`tr` 会引入 React，不要在后台里用。
- **自带 `{}` 或 `<>` 的文字**（协议样例、语法速查）键以 `.raw` 结尾，用 `raw()` 取，不做任何替换。
- **一条文案是一整句话。** 不要把几个译好的片段在代码里拼成句子，也不要靠词序拼接；代码里用条件选词的，写成两个键，条件留在代码里。
- **不要在模块顶层调用 `t()`。** 语言在页面启动时才选定，顶层调用会锁死模块加载那一刻的语言。含文案的静态表（`GROUPS`、`SOURCE_INFO` 等）只存键，显示的地方再 `t()`。
- **键名**：`区域.模块.含义`，小驼峰，如 `options.ai.summaryTitle`；按枚举成表的用 `表名.枚举值`，如 `source.label.google`、`mode.web`。

## core 的几句话

core 不认识界面语言。它写给用户看的只有 8 句（为什么某项功能没用上、用户自己规则的名字），通过 `Env.messages` 传入，没传的用 core 自带的中文默认值（`DEFAULT_CORE_MESSAGES`），所以 MCP 和测试不传也有话说。扩展在 `makeEnv` 里用 `coreMessagesFor()` 从语言包生成。`test/coreMessages.test.ts` 保证语言包里的中文和 core 默认值一致。

core 里其他的中文不是界面文字：提示词是给模型的，引擎解析用的正则是匹配对方网站的文字，`meta.siteName` 的 `知乎`、`微信公众号` 是引擎写进结果的数据（扩展里比较它的行带 `i18n-ignore` 注释）。屏蔽列表的说明是界面文字，已从 core 搬到设置页的语言包。

## 选哪种语言

页面和后台启动时调用 `initLocale()`，按浏览器的语言偏好（`navigator.languages`）选一种已有的语言，没有就用中文，并设置 `<html lang>`；设置页还会设置标题。只有中文时这一步什么也不改。还没有“界面语言”设置项，要做时在 `initLocale` 前读设置即可。

“AI 概览用什么语言写”（`summary.language`）是另一回事：它决定模型的回答语言，与界面语言互不影响。

## 加一种语言

1. 在 `catalog/` 旁新建一个文件，导出 `Partial<Record<MessageKey, string>>`，键用中文包的键，占位符和 `<标签>` 要与中文一致。缺的键会自动用中文，所以可以没翻完就上线。
2. 在 `index.ts` 里传给 `createI18n(zhCN, 'zh-CN', { en })`。
3. `pnpm --filter @kiwi-search/extension test`：`packages/app/test/i18n.test.ts` 会逐条检查译文用的键中文里有、占位符和标签与中文一致。
4. 有复数的语言（英文的 “1 result / 2 results”）要先扩展 `runtime.ts` 的 `formatMessage`；中文没有复数，现在不支持。
5. 数字、日期还有 `toLocaleString()` 没带语言的地方，以及“x 分钟前”这类相对时间（现在是文案，不是 `Intl.RelativeTimeFormat`），要按语言处理。

## 检查

| 测试 | 查什么 |
|---|---|
| `test/noHardcodedText.test.ts` | `entrypoints/` 和 `lib/` 里不许再出现中文字符串、模板或 JSX 文字（语法树扫描，注释不算）。数据可在同一行写 `i18n-ignore` |
| `packages/app/test/i18n.test.ts` | 格式、取词、语言选择、语言包的键名和标签，译文与中文的占位符一致 |
| `packages/app/test/i18n.types.tsx` | 类型层面：键、占位符、动态键的穷尽检查（`pnpm typecheck` 跑它） |
| `test/coreMessages.test.ts` | 语言包里 core 的几句话与 core 默认值一致 |
| `packages/app/test/copyStyle.test.ts` | DESIGN.md “Copy” 里能机器检查的规则：不用“您”和感叹号、术语表里的禁用词、中文与英文数字之间留空格等 |

## 不在这里的

- **MCP 包**的输出（工具说明、结果文字、stderr）是给 Agent 和终端看的，没有走语言包。
- **扩展清单**里的名称和描述（`wxt.config.ts`）是英文，没有用 `_locales`；上架多语言商店页时再做。
- **发给模型的提示词**是英文，不属于界面。
- **搜索结果本身**（标题、摘要、作者）是对方网站的文字，不翻译。
- README 和 `docs/` 是写给中文读者的文档，不走语言包。
